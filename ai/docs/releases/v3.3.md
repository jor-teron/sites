# v3.3 — Verbose startup diagnostics

## Purpose

Make server startup easier to understand and troubleshoot without changing the
MCP protocol, authentication model, sandbox design or network configuration.

## Changes

- `mcp.sh` reports six startup stages: configuration, workspace/state setup,
  sandbox prerequisites, existing-process/port checks, launch, and HTTP health.
- Prints non-secret configuration details, including version, bind address,
  workspace, sandbox mode and whether authentication is enabled. It never
  prints the PIN.
- Checks directory writability and port conflicts before launch.
- Background startup reports the PID, local endpoint, health endpoint and log
  path, and detects an early process exit.
- `--quiet` suppresses progress steps while retaining important results and
  errors; use it before a command, for example `./mcp.sh --quiet --bg`.

## Validation

- Full automated suite: 162 tests passed, no failures or skips.
- Shell syntax checks passed for `mcp.sh`.
- Python compile checks passed.
- `git diff --check` passed.

## Compatibility

No API or MCP protocol changes. Existing start/stop/status commands remain;
startup is more descriptive by default. The optional `--quiet` prefix provides
compact output for scripts or users who prefer the previous style.
