# v3.5 — API integration verification preparation

## Purpose

Improve confidence in the standalone API client and make the remaining real-host
verification repeatable without pretending that isolated-jail tests prove live
HTTP connectivity.

## Changes

- Added client tests for connection refusal and invalid JSON responses.
- Added CLI environment-variable coverage for `API_URL` and `API_PIN`.
- Added coverage for missing PIN-file errors.
- Added `docs/v4-phase3.1-api-integration-verification.md` with safe Debian-host
  commands for health, authenticated tool discovery, a read-only tool call,
  wrong-PIN rejection, and MCP/API process independence.
- Clarified that version labels advance by integer component (`3.9`, `3.10`,
  `3.11`), never as decimal numbers.

## Validation

- API service and client tests: 14 passed.
- API HTTP integration tests: 16 skipped because the isolated environment
  blocks local TCP loopback.
- Existing MCP suite: 173 passed, 45 skipped due to loopback/live jail-network
  restrictions.
- Python compilation, CLI/server help, shell syntax, and `git diff --check`:
  passed.
- Debian-host live HTTP validation remains pending while the host is unavailable.

## Compatibility and safety

No API endpoint, authentication model, process lifecycle, default bind address,
MCP port 10001, or Tailscale Funnel configuration changed. API remains a
separate loopback-bound process on port 10002 by default.
