# v3.4 — Standalone API client

## Purpose

Make the independent HTTP API practical to use from scripts and a terminal,
without adding third-party dependencies or coupling its process lifecycle to
the MCP server.

## Changes

- Added reusable `APIClient` in `api/client.py`.
- Added `python3 -m api.client` commands for `health`, `tools`, and `call`.
- Added `API_URL`, `API_PIN`, `API_PIN_FILE`, `--url`, `--pin-file`, and
  `--timeout` configuration.
- Added JSON output, readable HTTP/connection errors, argument validation,
  and non-zero exit statuses for failures.
- Documented CLI usage in `README.md` and implementation details in
  `docs/v4-phase3.0-api-client.md`.

## Validation

- API service and client tests: 10 passed.
- Existing MCP suite: 173 passed, 45 skipped because this isolated environment
  blocks local TCP loopback and live jail networking.
- API HTTP integration suite: 16 skipped because local TCP loopback is blocked.
- Python compileall, CLI help/argument smoke checks, shell syntax, and
  `git diff --check`: passed.
- Real API HTTP connectivity still requires validation on the Debian host.

## Compatibility and safety

The API remains a separate process on its configured port (default
`127.0.0.1:10002`). MCP port 10001 and existing Tailscale Funnel routing are
unchanged. The API is not publicly exposed. No RAG, storage, or new permission
surface was introduced.
