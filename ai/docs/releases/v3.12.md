# v3.12 — RAG persistence

Phase 5.1 adds `RAGStore`, an explicit repository over the existing SQLite
storage package. Documents and chunks are stored in separate `rag.documents`
and `rag.chunks` namespaces. Saving or updating a document and replacing its
chunks happens in one transaction. Document IDs are stable for a source label;
content SHA-256 hashes identify normalized text and deduplicate identical
content across different source labels.

The repository supports save/update, full retrieval, metadata-only listing,
content-hash lookup and atomic deletion. It requires an explicitly initialized
`storage.Database`; it does not read environment variables or initialize the
database itself. No MCP/API integration, server startup changes, embeddings,
vector index or semantic retrieval are included.

Validation: 25 RAG ingestion/persistence tests, 24 storage tests, 14 API
service/client tests and 173 MCP tests passed. 16 API HTTP tests and 45 MCP
tests were skipped because the isolated Laptop MCP environment blocks local
TCP loopback/live jail networking. Python compilation, shell syntax and
`git diff --check` passed.
