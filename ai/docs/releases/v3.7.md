# v3.7 — Storage reliability

Phase 4.1 improves the opt-in SQLite package with `integrity_check()`, online
backup and validated restore. Restore stages a verified copy beside the active
database and atomically replaces it only after validation succeeds. Backup
files are permission-restricted and symbolic-link paths are rejected.

Tests cover backup/restore round trips, invalid backup rejection, integrity
checks, concurrent writers and transaction rollback. Storage remains opt-in
and is not connected to MCP/API startup or exposed as a tool. See
`docs/v4-phase4.1-storage-reliability.md`.

Validation: 16 storage tests, 14 API service/client tests and 173 MCP tests
passed. 16 API HTTP tests and 45 MCP tests were skipped because the isolated
Laptop MCP environment blocks local TCP loopback/live jail networking.
