# v3.8 — Storage configuration and access policy

Phase 4.2 adds `StorageConfig`, an explicit environment configuration layer
for the opt-in SQLite package. `AI_STORAGE_PATH` is required to enable it;
`AI_STORAGE_BACKUP_DIR` is optional and `AI_STORAGE_TIMEOUT` defaults to five
seconds. Configuration creates no files and returns an uninitialized database
object; callers must explicitly initialize it.

The release documents which future application services may use storage,
keeps MCP/API handlers and generic workspace tools outside that boundary, and
defines a manual backup policy. No server startup integration, backup
scheduler, automatic pruning, memory service or RAG feature is added.

Validation: 24 storage configuration/database tests, 14 API service/client
tests and 173 MCP tests passed. 16 API HTTP tests and 45 MCP tests were
skipped because the isolated Laptop MCP environment blocks local TCP
loopback/live jail networking. Python compilation, shell syntax and
`git diff --check` passed.
