# v3.13 — RAG retrieval foundation

Phase 5.2 adds chunk-level keyword retrieval to the existing RAG repository.
`RAGStore.initialize_search()` explicitly creates/rebuilds an optional SQLite
FTS5 index. `RAGStore.search(query, limit=10)` returns matching chunks with
source, title, content type, document ID, chunk index and source offsets. FTS5
uses SQLite BM25 ranking; lower scores are better.

If FTS5 is not compiled into SQLite, initialization returns `False` and search
continues using parameterized SQLite LIKE matching. Search works without
initializing the FTS index, though the fallback is slower and does not provide
relevance ranking. Result limits are bounded from 1 to 50. Every query term
must match.

Index creation/rebuild is explicit. Once created, document saves/updates and
deletes update the FTS index inside the same SQLite transaction as document
and chunk records. No server startup integration, MCP tools, API endpoints,
embeddings, vector database or semantic retrieval are included.

Validation: 30 RAG tests, 24 storage tests, 14 API service/client tests and
173 MCP tests passed. 16 API HTTP tests and 45 MCP tests were skipped because
the isolated Laptop MCP environment blocks local TCP loopback/live jail
networking. Python compilation, shell syntax and `git diff --check` passed.
