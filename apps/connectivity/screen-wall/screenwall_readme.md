# Multi-Screen Wall — MW1

Join several phones, tablets or PCs on the same Hub Connect Code into one big screen (Connectivity → Share). One device is the **Host**; every other device is a **Display** that shows only its own slice of the big wall.

- **Code:** `#code=1234` / `?hub=` (QR), the Hub's `{sharedLink:'hello'}` after `{sharedLink:'ready', app:'screen-wall'}` inside the Hub, `parent.__hubRemote.code`, `jtsites-hub-ctrl-code` / `shared-link-join-code`, the last code (`screenwall-last-code`), else the Code dialog.
- **Peers (own, never the Hub's):** `jtsites-<code>-screenwall-<random>` per device; lobby `jtsites-<code>-screenwall-0` is claimed by the first device, keeps the roster (`hi {id, info:{name, dev, role, since, w, h, dpr}}` → `roster`) and relays `{t:'all'}` / `{t:'to'}`. If the lobby goes, a remaining device claims it (random 0.3–1.8 s). PeerJS from `SharedLink.PEERJS_URL` (`shared/link/link_core.js`), pinned peerjs 1.5.4. Data connections only.
- **Host (Wall screen):** live preview of the whole wall with the grid on top. Rows 1–4 × columns 1–6. Drag a device tile from the list into a cell (or tap the tile, then a cell); drop on an occupied cell swaps; drag back to the list to remove. Auto-place fills free cells. Each tile shows name, CSS size and pixel ratio, plus **Identify** (the device flashes its big number for 3 s). **Bezel** slider (0–120 px) = hidden gap between neighbouring screens so lines run straight across the frames.
- **Layout maths:** column width = widest device in that column, row height = tallest in that row (empty cells 480 × 300); each device is centred in its cell; rect `{x, y, w, h}` in wall px is what it shows.
- **Content screen (host):** Test pattern (Grid with coordinates, Gradient, Solid), big Clock, Scrolling text (speed, size), Picture (compressed to JPEG ≤ 1920 px, sent once in 16 000-char chunks; late joiners ask with `need`; Fill / Fit). Text and background colours.
- **Displays:** Full screen button (or tap the slice, or F) → Fullscreen API + Screen Wake Lock (re-taken when the page comes back); inside the Hub frame without fullscreen permission the slice still fills the frame, and "Open as its own page" opens it standalone. Windowed, the slice is scaled to fit. Size changes are re-reported to the host.
- **Clock sync:** displays ping the host (5 quick, then every 10 s); offset = host time − midpoint of the ping, from the lowest round trip of the last 8. Clock and scrolling text use host time, so every slice is in step.
- **One host:** taking over asks first (in-app dialog); the older host turns into a display.
- **Files:** `screenwall_save.js` (the one save module: `screenwall-settings-v1` `{name, theme, role}`, `screenwall-state-v1` host layout + content, `screenwall-image-v1` last picture, `screenwall-last-code`, theme), `screenwall_peer.js` (presence + relay), `screenwall_wall.js` (layout + drawing + picture compress/chunks), `screenwall_app.js` (UI, roles, editor, sync, full screen, swipes, dialogs).
- Screens: Wall · Content · Settings (dots, 75 px wrap-around swipes; no swipes in full screen or on tiles). Dark by default; Theme System/Light/Dark (System follows `sites-hub.theme`).
- **Not in MW1:** video on the wall (planned for MW2), per-device physical-size calibration (screens with very different pixel densities show content at different physical sizes), the host showing a slice itself.
